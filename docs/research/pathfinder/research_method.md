# Метод и воспроизводимость

Проверено13ноября2026, Europe/Kyiv. Broad search → platform-policy check → source filtering → comparison → economics → adversarial review. Не задавали квоту положительных идей. Genesis PR#2 прочитан как отрицательные данные: цена/часы/воронка не были доказаны.

Отбор: конкретный повторяемый процесс и paid substitute; затем бесплатная замена, complaints и их независимость; затем first-buyer access. Нет доказанного трафика/оплаты → не рекомендовать full build. Одна complaint — ONE_OBSERVED, vendor FAQ не самостоятельный buyer, locale URLs с тем же app ID/текстом не отдельные сигналы. Вторичные comparison pages не превращаются в primary invoice. Сырые длинные чужие тексты и частные контакты не сохранялись.

Браузерные регистрации/входы не выполнялись; собственные автоматические запросы к marketplace listings/API не делались. Search/open provider использован для ограниченных публичных просмотров. Публичный Appodeal PDF скачан один раз для проверки периода/извлечения текста; длинный PDF не закоммичен. Не проверяли фактические store ranking, search volume, CPC/CPI, paid conversion и выплаты. Эти ограничения влияют на verdict, а не спрятаны в сноске.

Финансы воспроизводимы offline, но коммерческие inputs ASSUMED. Live search и будущая цена не воспроизводятся из CSV: реестр даёт source URL/дату/точный предел утверждения для повторной проверки. `validate.py` проверяет ссылки IDs, количество карточек, обязательные документы и арифметику. Это не тест бизнес-успеха. Налоги, фактические поступления, account-specific access и юридическое заключение не симулировались.
