# Партнёрская дистрибуция: 22 организации

[Построчная проверка](data/partners.csv) содержит для каждого партнёра механизм входа, условия допуска, уже продаваемые услуги, неизвестные потребности клиентов, white-label/revenue share, минимальный продукт и причину купить его вместо собственной разработки. Источники, даты и ограничения — [реестр](data/evidence_registry.csv).

Исследованы агентства P16–18, CRM/ERP P04–10, автоматизация P01–03, hosting и агентское исполнение P11–13, поставщик MSP-инструментов P14, небольшой B2B SaaS P19/20 и vendor distribution P15. Поставщик ПО для MSP не приравнен к самому MSP-покупателю. Нерешённые потребности их клиентов остаются UNKNOWN: партнёрская реклама их не раскрывает.

| Организации | Что подтверждено | Что не подтверждено |
|---|---|---|
| Make / Zapier | Заявка, обучение, referral benefits | Покупка нашего ПО и первые показы |
| n8n | Закрытый пилот, минимум три клиента и географический фокус | Вход основателя без клиентов; текущий путь BLOCKED |
| Pipedrive / HubSpot / Zoho | Заявки технологических/консалтинговых партнёров, требования к листингу | Допуск и оплаченная интеграция |
| Odoo / Frappe | Формальные ERP-программы; в условиях Frappe есть требование ресурсов команды | Дешёвый вход одного человека без отраслевой экспертизы |
| SendPulse agency | Сертификация и два платящих клиента для каталога | Получение первых двух клиентов через этот каталог |
| SendPulse integration [S28] | Помощь, ссылка, анонс, возможная выплата/комиссия по сложности | Конкретный funded gap, чек, контракт, объём показов |
| Kommo | Открытая заявка и услуги внедрения CRM | Первые referral leads и индивидуальные условия для Украины |
| Cloudways / Kinsta | Агентские программы и заявленные benefits, часть зависит от условий/tier | Покупатели нашего acceptance kit |
| GoWP | Продажа white-label исполнения агентствам | Приём нас как поставщика и передача своих клиентов |
| EasyDMARC | MSP reseller portal | MSP, согласившийся покупать наш модуль |
| Vendasta | Явная заявка ISV как vendor | Активация реселлеров, маржа и продажи нашего продукта |
| Swanky / Owl and Monk | Технологические партнёрства / миграционные услуги | Открытый приём внешних подрядчиков; клиентская форма не доказательство |
| Maukau | Явная категория контакта «партнёрства» | Бюджет, white-label, желание отдать приёмку внешнему исполнителю |
| Plausible | Разрешённое bundling/white-label аналитики в рамках продукта | Входящие клиенты для основателя без аудитории |
| AlgolPlus | Платный экспортёр и конкретный вопрос в support | Приём нашего модуля и отдельная покупательская готовность |

Во всех предложениях преимущество пока ASSUMED: повторяемые тесты могут сэкономить агентству часы, но внутренних затрат мы не измеряли. Агентство может написать тот же скрипт быстрее, чем проверить нового поставщика.

Короткий список для будущего разрешённого контакта — **два**, без квоты на пять:

1. **Maukau [P18]:** через явно обозначенный partnership intake проверить, покупают ли они независимую приёмку миграции. Предмет — конкретный отчёт и фиксированный объём. Успех — согласованный платный пилот, а не положительный ответ об идее.
2. **SendPulse [S28]:** выяснить, есть ли конкретная отсутствующая интеграция с заранее обсуждаемым вознаграждением и продвижением. Новый WooCommerce connector не предлагать: он уже существует [S29]. До ответа нет выбранного продукта или обещанной оплаты.

Vendasta оставить на этап после принятого продукта: vendor review может предполагать уже работающий продукт. Swanky — резерв только после установления подходящего supplier/tech intake. Не использовать общую клиентскую форму как доказательство открытого приёма поставщиков. Ничего не отправлено.

Дополнительно проверены реальные managed IT providers: **Ntiva [P21]** — найден клиентский intake на managed IT, не механизм приёма нас как поставщика; **Electric [P22]** — есть явная заявка на партнёрство и действующие IT/HR integrations, но purchase gap и доступ к клиентам UNKNOWN. Они добавлены отдельно от поставщиков ПО для MSP, чтобы не подменять эти категории. В короткий список первого контакта не включены из-за слабого соответствия export acceptance workflow.
