# Marketplace Signal Feasibility

Проверено 14.11.2026 по официальным документам. «Не установлен» означает отсутствие подтверждённого разрешённого метода в этом исследовании, а не математическое доказательство невозможности.

| Платформа | Новые продавцы / начало деятельности | Новые товары / ассортимент | Слабые карточки / новый рынок | Официальный доступ и ограничения |
|---|---|---|---|---|
| Allegro | Общий поток регистраций не установлен; первая обнаруженная оферта не дата регистрации | Собственные оферты авторизовавшего продавца; public discovery ограничен | Аудит своего каталога и доступных marketplace-полей после OAuth; качество требует рубрики и ручной проверки | `/sale/offers`, `/sale/product-offers/{offerId}` — свой продавец. `/offers/listing` нельзя считать доступным новому приложению |
| Amazon | SP-API не даёт общедоступный реестр новых продавцов; возраст аккаунта не доказывает начало торговли | Listings/Reports авторизовавшего продавца; Catalog Items описывает товары, не поток регистраций | Listings Issues и проверки контента собственного продавца; marketplaces/отчёты после авторизации, не глобальный мониторинг экспансии | Регистрация разработчика, роли и OAuth каждого selling partner; не использовать данные клиентов для чужого аутрича |
| Etsy | Документированы shop lookup/search и shop timestamps; это не доказательство полного потока новых магазинов или первой продажи | Listing API и timestamps в пределах одобренного доступа; сравнение снимков | Полнота фото/описания — признаки, не доказательство плохих продаж. Язык/валюта не доказательство экспансии | API key, OAuth для scoped endpoints, одобрение коммерческого сценария; broad discovery для аутрича отдельно не одобрен |
| eBay | Browse находит объявления, не регистрации продавцов; first seen ≠ seller join date | Browse search/Feed при разрешённом production-доступе; coverage, категории, площадки ограничены | Доступные поля объявлений; marketplace публикации не доказывает новую стратегию продавца | Developer account/OAuth application token; Buy production eligibility и условия использования. Lead-gen не считать автоматически разрешённым shopping use case |
| Shopify | Нет общего официального API «новые магазины»; новая видимость домена не дата запуска | Admin GraphQL после установки приложения и read-scopes; webhooks собственного merchant | Аудит согласившегося магазина; Markets и локализация после доступа | Storefront API обслуживает витрину, не глобальный каталог merchant-ов. Admin требует store-specific token |
| WooCommerce | Нет центрального реестра self-hosted магазинов | Публичный Store API даёт опубликованные товары известного сайта; admin REST только с ключами магазина | Отсутствующие изображения/описания — проверяемый дефект; локали/домены лишь косвенная экспансия | Store API без ключа технически доступен, но заявлен для customer-facing storefront; мониторинг чужого сайта требует проверки условий/согласия владельца |

## Allegro: отдельная актуальная проверка

Официальный collaborator в [issue 13780 от 27.07.2026](https://github.com/allegro/allegro-api/issues/13780) сообщил, что в ближайшее время возобновление верификации приложений для listing не планируется; получать детали чужой оферты через предполагаемый `/offers/{offerID}` также нельзя. Он указал собственные оферты авторизующего пользователя как доступную альтернативу. Это сильнее старых SDK, где endpoint остаётся описанным. [Текущая документация](https://developer.allegro.pl/documentation/) и [issue 14126](https://github.com/allegro/allegro-api/issues/14126) — точки повторной проверки перед инвестицией.

Вердикт: public offer discovery существует в документации как ограниченная возможность, **но подтверждённого пути доступа нового приложения нет**. Старые verified apps не означают право нового разработчика использовать их ключи/выгрузки. Старый URL новости об ограничении вернул 404 через web-поиск; на него вывод не опирается. Тест production с ключом не проводился.

## Стоимость, свежесть, полнота и провайдеры

| Платформа | Стоимость и свежесть | Полнота | Коммерческие поставщики |
|---|---|---|---|
| Allegro | Текущие тарифы/условия разработчика не подтверждены; квоты проверять после одобрения | Собственный продавец; global discovery недоступен пилоту | Подтверждённый поставщик с лицензией на наш lead-gen не найден |
| Amazon | [SP-API](https://developer-docs.amazon.com/sp-api/docs/connecting-to-the-selling-partner-api) требует onboarding; стоимость на дату отчёта не подтверждена, бесплатность не предполагается; квоты endpoint-specific | Авторизованные продавцы; лаг зависит от reports/notifications | Keepa и подобные product-data сервисы не доказывают лицензию на новых продавцов/контакты; не утверждаем разрешённость, не включаем |
| Etsy | Тариф и квоты коммерческого кейса требуют подтверждения; не предполагаем real-time | Только выданные scopes/лимиты; timestamps ≠ продажи | Название eRank/Alura не заменяет доказательства прав; не одобрены этим исследованием |
| eBay | Квоты и расходы по контракту/Developer Program; freshness листинга зависит от API | Не весь каталог и не все seller events | Допуск третьей стороны к Buy API не разрешает дальнейшую перепродажу lead-data |
| Shopify | Тариф приложения/магазина и API costs проверить; webhook latency не измерен | Только установившие приложение магазины | BuiltWith/Wappalyzer предлагают technographic leads; это даты обнаружения технологий, не регистрации магазинов; условия downstream reuse проверять |
| WooCommerce | Нет центрального тарифа API; хостинг/обработка/ручной аудит платные | Только выбранные доступные магазины | BuiltWith/Wappalyzer: законность конкретного набора, источников и перепродажи требует контракта |

Для всех шести платформ **не подтверждён разрешённый универсальный провайдер нового seller registry**. Это не утверждение, что ни одного провайдера не существует. Неофициальный API, marketplace в Apify или возможность открыть URL не считаются разрешением.

## Запрещённые и условно допустимые методы

Не использовать CAPTCHA/anti-bot bypass, чужие аккаунты, приватные endpoints, customer/order PII, scraping без разрешения, скрытый обход лимитов или seller messages для рекламы услуг без допустимого основания. Etsy явно ограничивает automated scraping в [API Terms](https://www.etsy.com/legal/api/). Для остальных применять только одобренный API/use case и актуальные terms; robots.txt сам по себе разрешение не создаёт.

Первичные документы: [Amazon authorization](https://developer-docs.amazon.com/sp-api/docs/authorizing-selling-partner-api-applications), [Etsy developer portal](https://developers.etsy.com/documentation/), [eBay Browse](https://developer.ebay.com/api-docs/buy/api-browse.html), [eBay production requirements](https://developer.ebay.com/api-docs/buy/buy-requirements.html), [Shopify authentication](https://shopify.dev/docs/api/usage/authentication), [WooCommerce Store API](https://developer.woocommerce.com/docs/apis/store-api/). API доступ и разрешение на коммерческое переиспользование — разные проверки.
