Более сильная комбинация: **опубликованная задача + конкретный дефект или объём + срок + доступный официальный процесс ответа + способность исполнить**. Более слабая: компания зарегистрировалась, домен появился, вакансия опубликована. Два слабых сигнала не превращаются автоматически в подтверждённый спрос.

## Отрицательные проверки

- «Пустое описание» может быть вариантом товара, schema issue или намеренным кратким описанием. Сначала исключить ошибки извлечения.
- Новые SKU могут быть дубликатами/вариантами/перезапуском; сравнить stable IDs и базовый снимок.
- Вакансия full-time с запретом agency — исключение, а не лид для контент-агентства.
- Закупка SaaS-лицензии — часто не заказ на разработку; интеграционное сопровождение нужно доказать отдельно.
- Опубликованный бюджет всего framework не означает guaranteed spend или бюджет доступного нам lot.
- Глобальная API migration создаёт общую техническую возможность; затронутые компании без их согласия/инвентаризации не установлены.

Приоритет отраслей для проверки: образовательные организации (контент и локализация с небольшой отдельной задачей), B2B software/integrators (документированные миграции у согласившихся клиентов), публичные организации с малыми закупками сайтов/доступности. Финансовые/медицинские крупные IT и safety-critical оборудование в пилоте отсеивать по capacity и compliance, несмотря на крупные суммы.
