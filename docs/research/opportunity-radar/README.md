# Ninja Opportunity Radar — решение по исследовательскому пилоту

Дата отчёта: **14 ноября 2026, Europe/Kyiv**. Сбор: 13 ноября UTC (точные времена в журнале). Отдельная ветка `research/ninja-opportunity-radar`, основана на `origin/main`. Изменения ограничены этой папкой. Ни CRM, ни production-бот не изменены; сообщений не отправлено.

**Решение: не строить радар регистраций продавцов Allegro/Amazon. Продолжить только узкую ручную проверку событий, где есть опубликованная коммерческая задача.** Законный общий поток новых продавцов для нового приложения не установлен. Согласившиеся продавцы — отдельный сценарий аудита собственных каталогов, а не discovery потенциальных клиентов.

## Что фактически получено

- Find a Tender: 500 свежих записей, пять страниц официального OCDS API, OGL v3.
- TED: первые 100 из 1 263 совпадений ограниченного запроса по IT/маркетингу/переводам с 9 ноября; это не полная выборка.
- Companies House: **одна синтетическая запись**, отдельно маркированная; нет ключа, реальных запросов не было.
- 600 реальных записей, 20 кандидатов по названию; 3 активных закупки с совпадением услуги. Это **не три квалифицированных лида**.
- 20 проверяемых карточек для первичного разбора, включая 15 завершённых закупок. **Ноль карточек допущено к обращению**, контактный маршрут и способность исполнить не проверены.
- 100% записей имеют ссылку на первоисточник, но это не означает успешное открытие каждой страницы или проверку всей документации.

## Воспроизведение

Python 3.11+, без зависимостей и без API-ключей для offline-проверки. Из корня репозитория:

```sh
python docs/research/opportunity-radar/prototype/radar.py --out /tmp/radar-results --as-of 2026-11-14T00:00:00Z
python -m unittest discover -s docs/research/opportunity-radar/prototype -v
python docs/research/opportunity-radar/prototype/radar.py --out /tmp/radar-replay --previous /tmp/radar-results/state.json --as-of 2026-11-14T00:00:00Z
```

Результат: JSON, CSV, state и benchmark. Повтор с прежним state должен дать `unchanged` для всех записей. Первый снимок всегда `baseline_observation`, а не «новый бизнес». `newly_observed` тоже не доказывает регистрацию или начало деятельности.

Опциональное получение нового снимка: `python docs/research/opportunity-radar/prototype/collect.py`. Команда заменяет файлы данных и журнал; сначала сделайте рабочую копию папки. Окно TED зафиксировано для исследования; для будущего запуска измените его явно. Максимум 6 запросов, timeout 30 секунд на запрос, остановка при ошибке; обходов нет. Снимок FTS закрепляет `updatedTo` в курсоре; токен TED второй страницы не используется, лимит явно отражён.

## Уровень доказательств

`confirmed_demand` = опубликован запрос на закупку соответствующего типа; не доказательство соответствия поставщика, выделенного нам бюджета или готовности купить именно нашу услугу. `probable_need` = требуется проверка задачи. `weak_indirect` = только косвенное событие. `false_positive` = не подходящее открытое предложение в этом пилоте (в том числе завершённая закупка).

Отчёт — исследование доступности, не заключение о законности любой будущей обработки. Непроверенные лицензии, стоимость и полнота помечены; общественный доступ не равен разрешению на scraping, контакт или перепродажу.
